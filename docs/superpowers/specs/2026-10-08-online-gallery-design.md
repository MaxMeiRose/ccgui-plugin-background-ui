# 在线图库与背景设置设计

用户目标：将 https://wp.upx8.com/#overview 壁纸 API V2.0 接入当前插件，支持分类、关键词查找、看图，并复用已有历史。用户已明确要求设计和执行。

## 设置页与交互

- 一级页签：主题配色、背景壁纸、界面细节。默认显示背景壁纸，保持已有主题、幕布及界面开关功能。
- 背景页上半部分显示当前图片、启停、铺满/完整显示与阅读遮罩。
- 图片来源区域：在线图库、本地导入、历史记录。默认显示历史，只有打开在线图库才访问网络。
- 在线图库提供分类、关键词输入、分辨率偏好、搜索/刷新；一次最多 10 张，没有下一页或总数承诺。提交关键词搜索时退出分类筛选，点击分类时清空关键词。
- 结果卡片有缩略图、可用标题/尺寸、预览入口；预览与应用分离。用户可以设为背景并自动加入历史，也可以仅保存到历史。
- 历史继续支持内容哈希去重、缩略图、重启恢复、离线使用、当前图片标识与确认删除；来源信息以可选字段保存，不改变旧版本历史索引。
- 图片缓存有容量上限；失败卡片可以重试。旧请求不得覆盖新查询，页面关闭或插件卸载后不得应用晚到结果。

## API 契约

API 请求使用 `https://wp.upx8.com/api.php?format=json&count=10`；参数 `content` 最长 100 字符、优先于 `category`；分类及分辨率取官方枚举。单张的 data 为对象，多张为数组。标题可为空、宽高可为 0，不把请求分辨率当作实际尺寸。

服务每 IP 每分钟 60 次，文档说明服务器缓存 5 分钟。不给请求增加未经文档支持的翻页、随机种子或缓存绕过参数。普通刷新可以返回重复图片；一批内按规范化 URL 去重。HTTP 429 提示稍后重试，503/无效响应显示错误并允许重试。

## 图片传输与宿主

当前宿主 `plugin_http_request` 将响应字节按 UTF-8 lossy 转为文本，不能保存 JPEG/PNG 原始字节。采用已有授权桥的可选 `responseEncoding: "base64"`，不使用浏览器直连、代理转码或外部执行器。

- 现有文本模式 `{status, body}` 保持兼容。
- base64 模式返回 `{status, body, encoding:"base64", contentType, byteLength, url}`，body 为原始字节的 base64。
- 保持实际接收字节不超过 8 MiB、连接/请求超时与域名/端口授权；校验每次重定向目标。只向已授权的 HTTP(S) 主机发请求，不允许跨主机转发凭据。
- 插件检查 encoding、base64 长度、图片文件头及解码尺寸，再走原有图片导入。旧宿主不支持时给出明确升级提示，不把文本伪装成图片。
- 图片可保存后采用本地 data URL；CSS 注入不包含远程 URL。
- 插件声明 API 与实际图片源的精确域名，不使用通配或 exec 权限。

本次将必要的宿主扩展与插件一起交付。原生能力需要重新构建/更新 CC GUI；不能把浏览器模拟宿主验证描述成已更新用户正在运行的客户端。

## 实现边界与取舍

选择向后兼容的原生桥增强：可靠保留原图并利用现有授权。浏览器直接加载绕过插件网络门禁，不采用；额外 Node 下载服务增加依赖及进程管理，不采用。

只修改本功能涉及的插件文件和宿主桥/SDK/对应文档及测试。宿主工作区已有未提交改动，必须保留；不提交、不推送、不重置工作区。插件是用户指定的可安装目录，不另外创建交付目录或改插件 ID。

## 验收

1. 真实 API 查询及至少一张真实图片下载可用，二进制往返不损坏。
2. 分类、关键词、单对象/数组响应、空标题/尺寸、去重、授权域名、429/503、旧宿主、损坏及超限图片有覆盖。
3. 在线应用和仅保存都进入同一历史；同图不增加记录，旧历史仍能读取，离线历史不会访问网络。
4. 存储失败不会把未保存图片报告成已入历史；旧请求和卸载后的请求不会变更背景。
5. 类型检查、插件构建、现有导入/历史回归和浏览器设置页验证通过；检查窄屏、亮/暗主题。
6. 生成根目录 main.js、styles.css，更新版本、说明和校验摘要，明确安装与宿主更新步骤。
